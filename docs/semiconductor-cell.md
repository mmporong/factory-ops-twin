# 반도체 최종검사·포장 구역

공장 범위는32×22m의 가상 후공정 최종검사·포장 베이다. JEDEC 소자 트레이를 ESD 운반 캐리어에 넣어 저장소와 테스트 핸들러 사이에서 이송하고, 검사 후 포장·출하 및 빈 캐리어 회수를 연결한다. 웨이퍼 전공정이나 OSAT 전체 공장을 재현하는 범위는 아니다.

## 실제 산업 공정과의 대응

[Advantest·STMicroelectronics의 사례](https://www.advantest.com/cn/news/2020/20201130.html)는 T2000 테스터, M4841 핸들러와 이동로봇이 트레이 저장소·설비 사이를 연결하고 MES가 lot 이력을 관리하는 구조를 설명한다. [ATE 설명](https://www.advantest.com/en/semiconductor-basics/automated-test-equipment/)에서 핸들러의 소자 공급·시험·분류 역할을 확인할 수 있다. 장면의 검사실, 입출력 트레이 승강부, HMI, ATE 캐비닛과 상태 표시등은 이 구성을 참고했다.

[Besi Datacon](https://www.besi.com/products-technology/product-details/product/datacon-2200-evo/)의 트레이·캐리어 처리 방식은 운반 단위의 참고 자료다. 해당 장비 본체 치수를 테스트 핸들러의 실측 치수로 전용하지 않는다. 제조사 CAD나 텍스처를 복제한 모델은 포함하지 않았다. 현재 장비는 공개 자료의 기능 구성을 참고한 비브랜드 절차형 OpenUSD 모델이다. 외부 자산을 추가할 때는 출처·파일 해시·이용 조건을 별도 기록한다.

## 설비와 배치

| 구역 | 장비와 역할 | 운영 연결 |
|---|---|---|
| 서쪽 LOT IN/WIP | ESD 트레이 로드포트, 트레이 스토커, lot 적치 구역 | S1/S2/S3에서 순차 공급 |
| 중앙 장비 열 | ATE 캐비닛, 검사·마킹 장비, ESD 작업대 | 후공정 보조 작업 구역 |
| 동쪽 공정 셀 | 테스트 핸들러, 트레이 승강부, AOI, 출력 롤러·포장대 | CI 입고, 논리 공정, CO 출고 |
| 출하 측 | 봉인·라벨·완성 트레이 대기 | OUT 인계 |
| 북쪽 | 필터·배전·유틸리티 캐비닛 열 | 설비 지원 구역 |

설비 외곽 점유 면적은 기존78.39㎡에서166.825㎡로 바뀌었다. 전체704㎡ 중 약23.7%다. 이는 설정된 설비 외곽 사각형의 합이며 실제 공장 포화도 표준이나 장비 본체 실측값이 아니다. 나머지 공간에는 AMR 이동 구역, 설비 접근·정비 공간, 도킹·대기 구역과 외곽 여유가 있다. 장비를 넣기 위해 이동 구역을 침범하지 않는다. 경로의 보수적인 단일 통로 예약은 유지하며, 높은 활용률을 위해 이를 해제하지 않는다.

모델은 단일 상자에 설비 이름을 붙이는 방식에서 트레이 수납·가이드·검사 창·승강부·제어 패널·ATE 랙 등 구성요소를 구분하는 방식으로 바뀌었다. 동적 캐리어를 놓는 지원면은 정적 소품과 겹치지 않게 비워 둔다. 개별 기계 내부의 정밀 동작과 인증된 클린룸·ESD 성능은 구현 범위에 포함하지 않는다.

외곽 정비·지원 공간에는 NVIDIA SimReady의 공구 캐비닛15개·이동식 작업대10개·정비 카트9개를 실제 모델 치수로 추가했다. 합산 외곽24.58㎡이며 이동·도킹·주차 구역과 기존 설비에서 최소0.1m를 비운다. 이 모델은 정비 지원용으로, 반도체 생산 설비나 인증 ESD 모델로 표시하지 않는다. 소비용 USD의 물리 API·관절 typed prim을 제거해 기존 충돌체20개는 유지된다. CPU 합성과 실제 Isaac Sim 조감·근접 RGB 두 장의 촬영·종료를 확인했다. [실제 촬영 근거](images/semiconductor-layout-local45-196/provenance.json) · [NVIDIA 출처·CC BY 4.0·준비법](asset-attribution.md)

## 반복 운영 로직

1. 세 저장소를 순환하는12개 lot를30초 간격으로 투입한다. 주문·트레이·캐리어 ID는 모두 고유하며 초기 재고가 유한하다.
2. FIFO에서 가능한 차량·일감을 선택하고 경로 점유, 버퍼와 가상 배터리 예산을 확인한다.
3. 실제 주행과 도착·정지 확인 후 트레이 인수·인계 및 원장 수량을 갱신한다.
4. CI의 두 lot 버퍼에서 논리 검사·포장 셀로 투입하고 CO로 내보낸다. 현재 공정은 단일20초 서비스 모델이다. 개별 테스트 장비의 병렬 처리나 실제 PASS/FAIL·수율·재검사 로직으로 표현하지 않는다.
5. 완성 lot는 OUT으로 운반하고 빈 캐리어는 해당 공급원으로 회수한다.
6. 하차한 차량은 다음 작업을 먼저 배차받는다. 다음 작업이 없으면2초의 배차 여유 후 주차장으로 이동해 작업장을 비운다. 새 stationary 인계 계약이 없는 같은 위치의 재인수는 배차에서 제외한다.
7. 투입이 끝난 뒤 미완료 작업·빈 캐리어를 정리하고 최종 주차·기록 종료를 확인한다. 이 시연 구간은 무한 주문 생성기가 아니다.

네 대가 항상 움직이는 것을 성공 조건으로 삼지 않는다. 병행 운송과 차량별 반복 인계, 대기 원인과 충전 복귀를 함께 보여준다. CPU의 작성된 이동·정차 모델에서는12개 lot 출하·12개 빈 캐리어 반납·재고60→36 보존·4대의 반복 참여와4개 동시 임무를 확인했다. 실제 물리 주행·예약·접촉·속도를 이 CPU 결과로 대신하지 않는다.

## 현재 구현 상태

설정은 `configs/factory-semiconductor/`에 있으며 기존 normal3 자료는 과거 실행의 근거로 보존한다. 새 배치의19개 설비 외곽,180개 경로 및4개 초기 주차 점유를 CPU에서 확인했다. [실제 Isaac Sim4.5 조감·근접 RGB](images/semiconductor-layout-local45-188/provenance.json)는 같은 정지 물리 시점의 두 촬영 결과다. 민트색 ESD 바닥 표현, 작업 구역 표시와 여섯 유틸리티 캐비닛을 포함하며 촬영 후 소유 프로세스 종료를 확인했다. 이 이미지는 제조사 CAD나 AI 생성 예상도가 아니다.

새 구성의 원속도 물류 GIF와 실제 혼합 운송 완주는 후속 실행에서 확인해야 한다. 기존 캐리어는 실제 Carter 장착 옵션을 재사용하지만, 트레이의 자동 적재·하역은 현재 원장·시각 표현이며 접촉 기반 자동 이송의 완료를 뜻하지 않는다.
